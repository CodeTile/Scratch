Here’s the **full end-to-end design** so your **Blazor app, API, and any future services all consume the exact same unified user context**, without duplicating auth logic anywhere.

The key idea is:

> Authentication happens per app, but **user context is generated once and standardised everywhere via a shared Security project**.

# 🧱 STEP 2 — Define the Unified User Context (IMPORTANT)

This is the shared model EVERY app uses.

```csharp id="s2"
public class UnifiedUserContext
{
    public string? UserName { get; set; }
    public string? DisplayName { get; set; }
    public string? Email { get; set; }
    public string? Department { get; set; }
    public string? JobTitle { get; set; }

    public bool IsAdUser { get; set; }

    public List<string> Roles { get; set; } = new();
}
```

👉 This becomes your **single source of truth for identity**

# 🧠 STEP 4 — Unified Context Builder (core engine)

This is the most important component.

```csharp id="s3"
public interface IUserContextBuilder
{
    Task<UnifiedUserContext> BuildAsync(ClaimsPrincipal principal);
}
```

---

## Implementation

```csharp id="s4"
public class UserContextBuilder : IUserContextBuilder
{
    private readonly AdService _adService;
    private readonly UserManager<ApplicationUser>? _userManager;

    public UserContextBuilder(
        AdService adService,
        UserManager<ApplicationUser>? userManager = null)
    {
        _adService = adService;
        _userManager = userManager;
    }

    public async Task<UnifiedUserContext> BuildAsync(ClaimsPrincipal principal)
    {
        var identity = principal.Identity!;
        var username = identity.Name;

        var context = new UnifiedUserContext
        {
            UserName = username
        };

        // -------------------------
        // AD USERS
        // -------------------------
        if (identity.AuthenticationType == "Negotiate")
        {
            var adUser = _adService.GetUserInfo(username);

            context.DisplayName = $"{adUser?.FirstName} {adUser?.LastName}";
            context.Email = adUser?.Email;
            context.Department = adUser?.Department;
            context.JobTitle = adUser?.JobTitle;
            context.IsAdUser = true;

            context.Roles = principal.Claims
                .Where(c => c.Type == ClaimTypes.Role)
                .Select(c => c.Value)
                .ToList();

            return context;
        }

        // -------------------------
        // IDENTITY USERS
        // -------------------------
        if (_userManager != null)
        {
            var user = await _userManager.FindByNameAsync(username!);

            if (user != null)
            {
                context.DisplayName = user.DisplayName;
                context.Email = user.Email;
                context.Department = user.Department;
                context.JobTitle = user.JobTitle;
                context.IsAdUser = false;

                context.Roles = principal.Claims
                    .Where(c => c.Type == ClaimTypes.Role)
                    .Select(c => c.Value)
                    .ToList();
            }
        }

        return context;
    }
}
```

# 🧠 STEP 6 — ClaimsTransformer (still used for UI)

This ensures Blazor UI remains simple.

```csharp id="s6"
public class ClaimsTransformer : IClaimsTransformation
{
    private readonly AdService _adService;

    public ClaimsTransformer(AdService adService)
    {
        _adService = adService;
    }

    public Task<ClaimsPrincipal> TransformAsync(ClaimsPrincipal principal)
    {
        var identity = (ClaimsIdentity)principal.Identity!;

        if (!identity.IsAuthenticated)
            return Task.FromResult(principal);

        var username = identity.Name;

        var adUser = _adService.GetUserInfo(username);

        if (adUser != null && identity.AuthenticationType == "Negotiate")
        {
            Add(identity, "display_name", $"{adUser.FirstName} {adUser.LastName}");
            Add(identity, "email", adUser.Email);
            Add(identity, "department", adUser.Department);
            Add(identity, "job_title", adUser.JobTitle);
            Add(identity, "is_ad_user", "true");
        }
        else
        {
            Add(identity, "is_ad_user", "false");
        }

        return Task.FromResult(principal);
    }

    private static void Add(ClaimsIdentity identity, string type, string value)
    {
        if (identity.HasClaim(c => c.Type == type))
            return;

        identity.AddClaim(new Claim(type, value));
    }
}
```

# 🌐 STEP 7 — Blazor usage (NO auth logic)

```razor id="s7"
@inject IUserContextBuilder UserContextBuilder
@inject AuthenticationStateProvider AuthStateProvider

@code {
    private UnifiedUserContext? user;

    protected override async Task OnInitializedAsync()
    {
        var authState = await AuthStateProvider.GetAuthenticationStateAsync();

        user = await UserContextBuilder.BuildAsync(authState.User);
    }
}
```

# 🧭 STEP 10 — What the UI uses

UI NEVER reads claims directly anymore:

### ❌ Avoid:

```csharp id="bad1"
User.FindFirst("department")
```

### ✅ Use:

```csharp id="good1"
UnifiedUserContext.Department
```

---

# ⚠️ RULES (important)

### ✔ Always:

* Build user context via `UserContextBuilder`
* Use claims only as transport layer
* Use `UnifiedUserContext` for logic

### ❌ Never:

* Duplicate AD logic in API or Blazor
* Read raw claims in business logic
* Rebuild user model in multiple places
