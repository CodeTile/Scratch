Since your clients are using both UseDefaultCredentials = true (Kerberos/NTLM) and explicit NetworkCredential(username, password, domain) (Active Directory credentials), both clients are strictly performing Windows Authentication.
Because both clients are using Windows Authentication, you do not need multiple authentication schemes (like JWT Bearer). Instead, you only need to configure Windows Authentication via the Negotiate handler to accept both current OS credentials and manually typed domain credentials.
Here is the correct, highly streamlined configuration for your .NET 10 API.
## 1. Install the Windows Auth Package
Run this command in your API project directory:

dotnet add package Microsoft.AspNetCore.Authentication.Negotiate

## 2. Configure Program.cs
You only need to register AddNegotiate and set it as the default authentication scheme.

using Microsoft.AspNetCore.Authentication.Negotiate;
var builder = WebApplication.CreateBuilder(args);
// 1. Register Windows Authentication (Negotiate handles both NTLM and Kerberos)
builder.Services.AddAuthentication(NegotiateDefaults.AuthenticationScheme)
    .AddNegotiate();
// 2. Add authorization services
builder.Services.AddAuthorization();

builder.Services.AddControllers();
var app = builder.Build();
// 3. Keep the correct middleware order
app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();
app.Run();

## 3. Configure launchSettings.json (Crucial Step)
For Windows Authentication to process the manual domain credentials correctly, Anonymous Authentication must be disabled so the server actively challenges the client for their Windows credentials.
Update your Properties/launchSettings.json:

{
  "profiles": {
    "http": {
      "commandName": "Project",
      "launchBrowser": false,
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      },
      "windowsAuthentication": true,
      "anonymousAuthentication": false
    }
  }
}

(Note: If you deploy your API to IIS or Azure App Service, you must similarly go into the settings, turn Windows Authentication ON, and turn Anonymous Authentication OFF).
## 4. Protect Your Controller
Decorate your controller or individual endpoints with the standard [Authorize] attribute. .NET will automatically parse and validate the Windows user context into the User object.

using Microsoft.AspNetCore.Authorization;using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/[controller]")]
[Authorize] // Enforces Windows Authentication automaticallypublic class AuthCheckController : ControllerBase
{
    [HttpGet("test")]
    public IActionResult CheckCredentials()
    {
        // Extracts the authenticated identity (Domain\Username)
        var identityName = User.Identity?.Name; 
        var isAuth = User.Identity?.IsAuthenticated ?? false;

        return Ok(new
        {
            Status = "Access Granted",
            WindowsUser = identityName,
            IsAuthenticated = isAuth
        });
    }
}

## Why this works for both of your client setups:

* Client 1 (UseDefaultCredentials = true): The client automatically sends the logged-in Windows user's Kerberos or NTLM token. The API verifies it against the current domain.
* Client 2 (NetworkCredential): The client sends a challenge response using the explicit username, password, and domain you provided. Because your API has AddNegotiate() active and Anonymous turned off, it validates those domain credentials directly against Active Directory.
