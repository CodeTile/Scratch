Yes — **but only if you deliberately capture both identities yourself**, because in a Blazor app running with **Windows authentication**, the app normally only sees **the identity that authenticated the HTTP request**.

So if you launch **Edge with “Run as different user”**, the app usually sees **that impersonated Windows user** as the authenticated user. It does **not automatically also know who originally launched Visual Studio or who is logged into Windows interactively**.

## The distinction

There are potentially **two different users** involved during local testing:

1. **The Windows user running Visual Studio / logged into the desktop**
2. **The Windows user the browser is running as** via **Run as different user**

For your Blazor app:

* `AuthenticationStateProvider` / `HttpContext.User` gives you **the browser-authenticated user**
  → this is the one AD / Negotiate uses for the app request

* it does **not** automatically give you the “original desktop user” as a second identity

---

# What you can show on the WhoAmI page

## Option A — show the **authenticated request user only**

This is the **important one for your app security**.

That’s what we already did:

```csharp
authState.User.Identity?.Name
```

If you run Edge as another AD account, this will show the impersonated browser user.

---

## Option B — also show the **machine’s current Windows identity from the server process**

You *can* show another identity such as:

```csharp
System.Security.Principal.WindowsIdentity.GetCurrent().Name
```

but be careful: in a Blazor Server app that value is **not “the original logged-in desktop user” in a reliable browser-testing sense**. It is the Windows identity of the **current server process / thread context** on the server side, which can be misleading depending on how the app is hosted.

For local development it can still be useful as a diagnostic field, but I would label it clearly.

---

# Recommended WhoAmI page for your scenario

This page shows:

1. **Authenticated request user** → the identity your Blazor app is actually using
2. **Server process identity** → useful for debugging during local impersonation tests
3. A simple flag to indicate whether they differ

## `Pages/WhoAmI.razor`

```razor
@page "/whoami"
@using System.Security.Claims
@using System.Security.Principal
@inject AuthenticationStateProvider AuthenticationStateProvider

<PageTitle>Who Am I</PageTitle>

<h1>Who Am I</h1>

@if (_requestUser is null)
{
    <p>Loading...</p>
}
else
{
    <div class="mb-4">
        <h3>Request / Authenticated User</h3>
        <p><strong>Name:</strong> @_requestUser.Identity?.Name</p>
        <p><strong>Authentication Type:</strong> @_requestUser.Identity?.AuthenticationType</p>
        <p><strong>Authenticated:</strong> @_requestUser.Identity?.IsAuthenticated</p>
    </div>

    <div class="mb-4">
        <h3>Server Process Identity</h3>
        <p><strong>Name:</strong> @_serverIdentityName</p>
    </div>

    <div class="mb-4">
        <h3>Comparison</h3>
        <p><strong>Different identities:</strong> @_differentUsers</p>
    </div>

    <h3>Claims</h3>

    @if (_claims.Count == 0)
    {
        <p>No claims found.</p>
    }
    else
    {
        <table class="table">
            <thead>
                <tr>
                    <th>Type</th>
                    <th>Value</th>
                </tr>
            </thead>
            <tbody>
                @foreach (var claim in _claims)
                {
                    <tr>
                        <td>@claim.Type</td>
                        <td>@claim.Value</td>
                    </tr>
                }
            </tbody>
        </table>
    }
}

@code {
    private ClaimsPrincipal? _requestUser;
    private List<Claim> _claims = new();

    private string? _serverIdentityName;
    private bool _differentUsers;

    protected override async Task OnInitializedAsync()
    {
        var authState = await AuthenticationStateProvider.GetAuthenticationStateAsync();
        _requestUser = authState.User;
        _claims = _requestUser.Claims.OrderBy(c => c.Type).ToList();

        _serverIdentityName = WindowsIdentity.GetCurrent()?.Name;

        var requestUserName = _requestUser.Identity?.Name ?? string.Empty;
        var serverUserName = _serverIdentityName ?? string.Empty;

        _differentUsers = !string.Equals(
            requestUserName,
            serverUserName,
            StringComparison.OrdinalIgnoreCase);
    }
}
```

---

# How to interpret the results

## `Request / Authenticated User`

This is the one that matters for authorization.

If you open Edge with **Run as different user**, this should usually be the impersonated AD account.

Example:

```text
CORP\alice.smith
```

---

## `Server Process Identity`

This is just diagnostic. During local dev it might be:

* your normal Windows account
* IIS Express identity
* app pool / process identity
* or something else depending on host

So I would **not** treat this as “the logged-in user” in a business sense. It’s just useful for debugging if you want to see whether the request identity differs from the server process identity.

---

# Important limitation

If by “show login user and impersonated user” you mean:

> “Show the person who is signed into Windows on the machine **and** the different AD user the browser is running as”

then **Blazor doesn’t automatically know that first one** in a trustworthy way for the web request. The app only really knows the identity attached to the request.

So the safest statement is:

* **Yes, you can show the authenticated browser/request user**
* **You can also show a server-side Windows identity for diagnostics**
* **No, there isn’t a built-in reliable “original desktop user” field automatically available to the app request**
