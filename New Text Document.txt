Right — and this is the key thing, Bruce:

### **Visual Studio 2026’s built‑in coverage UI (the one that replaced the old VS Enterprise coverage engine) only exposes:**
- **Assembly‑level exclusions**
- **Attribute‑based exclusions**

It **does NOT** expose:
- File‑level exclusions  
- Class‑level exclusions  
- Pattern‑based exclusions  
- “Ignore Program.cs” style rules  

That’s why you’re not seeing an option for `Program.cs` specifically.

And here’s the twist:

### **dotCover *does* support file‑level and class‑level exclusions — but ONLY through a dotCover configuration file.**

The Visual Studio UI simply doesn’t surface those options.

So the fix is:

---

# ✅ The correct way to exclude Program.cs in dotCover (VS2026)
Create a `dotCover.xml` file in your solution root:

```
<DotCoverSettings>
  <Filters>
    <ExcludeFilters>
      <FilterEntry>
        <ModuleMask>*</ModuleMask>
        <FileMask>*Program.cs</FileMask>
      </FilterEntry>
    </ExcludeFilters>
  </Filters>
</DotCoverSettings>
```

This excludes **any file named Program.cs**, regardless of project.

If you want to exclude only the top‑level Program class:

```
<ClassMask>Program</ClassMask>
```

Both work — the first is more reliable for .NET 6+ minimal hosting.

---

# ⭐ How to make Visual Studio 2026 actually use this file
VS2026 auto‑detects dotCover configs the same way it auto‑detects runsettings:

1. Put `dotCover.xml` next to your `.sln`
2. Restart Visual Studio
3. Run coverage again

If you already selected a different coverage config manually, VS will keep using that until you reset it.

---

# 🎯 Why the UI doesn’t show file‑level exclusions
Because the VS2026 coverage UI is built around:
- Assembly filters  
- Attribute filters  

dotCover’s full filtering engine is **only accessible via XML**, not the UI.

JetBrains never exposed file‑level filtering in the Visual Studio integration panel.
